按当前评测口径，`Qwen/Qwen3-VL-32B-Instruct` 在 75 张样本上四项 AC-128 门槛**全部未通过**，且差距是一个数量级，**NO-GO 方向成立、不因评分口径调整而翻转**。

## 3. 为什么这些数值不能作为模型能力结论

### 3.1 GT 未经人工逐字核对（根本性，违反 AC-128 前置）

75 行 `ground_truth.jsonl` **全部**带 `notes`，且都含：

> `公开数据集 LaTeX 仅作草稿，须人工逐字核对上下标/根号/积分限`

PRD §20.4 阶段 0 明确要求「由教师或标注人员制作逐字 / 逐公式 Ground Truth；数学公式必须人工核对上下标、括号、分数线、根号、积分上下限、极限方向和矩阵位置」。
抽样可见 GT 本身含错：s064 GT 为 `The position of sewerage is accounted for by`（`sewerage` 系错词），模型输出 `Stevenson` 反而更接近原意；s063 GT 混入 `one 7,000 employees` 一类拼接噪声。**模型的"误读"里混着 GT 错误**，CER 不可直接归因于模型。

### 3.2 样本是渲染 / 拼版合成，不是真实手写作业

按 `notes` 分布：29 张 `clean: 原样渲染`、20 张 `synthetic: 版面合成混排`（中文=教师自采手写行、英文=IAM 公开集、公式=渲染）、6 张 `multi_formula_plate` 拼版，其余为 blur / tilt / low_contrast 图像退化。
即绝大多数是**LaTeX 印刷体渲染图**，而 AC-128 要测的是「手写中文、英文、数字、公式及混排」。另有 55/75（73.3%）为纯公式样本，文本 CER 分母只有 20 张（clean 12）。用印刷体渲染图测手写识别，结论无法外推到真实作业照片。

### 3.3 严格 Exact Match 混入格式等价差异（存在，但非主因）

`normalize_latex()` 只做「去定界符 + 去所有空白」，不做语义归一化。抽样：

| 样本 | GT | 模型输出 | 性质 |
|---|---|---|---|
| s007 | `\sqrt{l \over g}` | `\sqrt{\frac{l}{g}}` | **等价**，TeX 分式写法不同 |
| s008 | `c_{1}e^{x}` | `c_1 e^x` | **等价**，花括号省略 |
| s005 | `2(\sqrt{2}-1)\approx 0.828` | `2(\sqrt{2} - 1) \approx 0.828` | **等价**，仅空格 |
| s048 | `2sin(x/2)` | `2\sin(x/2)` | **等价**，缺反斜杠 |
| s028 | `\sqrt[3]{v}` | `\sqrt[2]{v}` | **真实误读**，根指数 3→2 |
| s004 | `M=\mathbb{R}^{n}` | `M = R^\infty` | **真实误读** |

对 87 对可配对公式做归一化后相似度分级：

| 相似度 | 对数 | 占比 |
|---|---:|---:|
| 完全相等（命中） | 8 | 9.2% |
| ≥0.90 未命中 | 7 | 8.0% |
| 0.70 ~ 0.90 | 14 | 16.1% |
| 0.40 ~ 0.70 | 30 | 34.5% |
| <0.40 | 28 | 32.2% |

即便 ≥0.90 那 7 对里也混有真实误读（如 `\sqrt[3]{v}`→`\sqrt[2]{v}`、`\Omega(eg)`→`\Omega(e_g)`）。`--aggressive-latex` 仅把 EM 6.56%→7.38%，印证格式差异不是主因。

另有一处口径细节：报告记「数学公式区域数 122」，而 **GT 实际公式区域是 110**（clean 63）。因 `formula_score()` 按 `max(len(gt), len(pred))` 计分母，预测公式数与 GT 不等时缺/多均计未命中，分母被放大；仅 87 对能配对。

### 3.4 本次评测未覆盖 PRD 要求的完整对比

§20.4 阶段 0 要求「对路径 A（视觉模型）和路径 B（Mathpix）使用同一批样本；对中文手写文本额外测试路径 C（百度手写 OCR）」，§26.1 第 1 条要求输出「准确率、耗时、成本、**数据驻留**与**默认供应商建议**」。本次：

- 只跑了路径 A 的**一个**模型规格，`mathpix` / `baidu` / `cmd`（本地开源库）均未评测；
- 单价未配置 → 成本列恒为 0，无成本结论；
- 数据驻留未评估（图片经 API 出网到第三方）；
- 未形成默认 `OCR_PROVIDER` 与备选建议。

因此本次只是**单 provider 的首次实测**，不构成 Spike 选型结论。

## 4. 为什么 NO-GO 结论仍然稳固

不必靠放宽评分口径「救」模型：

| 项 | 实测 | 全部格式差异放宽后的乐观上界 | 阈值 |
|---|---:|---:|---:|
| 清晰文本 CER | 59.45% | 仍远高于 | ≤5% |
| 全部公式 EM | 6.56% | ~15% | ≥80% |
| 清晰公式 EM | 3.03% | ~10% | ≥90% |

即便把 §3.3 的等价差异全部计入，差距仍是**一个数量级**。按 §26.2「手写识别样本集达标；如未达标，先启用手工校正降级流程，不对外标注『准确识别手写作业』」与 §20.4「如果所有方案均未达门槛，先以『上传 + 手动校正题面 + 现有解题』作为降级版本」，动作明确。

⚠️ 但要区分两件事：**「不达标 → 启用降级」成立**；**「该模型手写识别能力 = 6.56%」不成立**。前者是流程决策，后者是能力断言，本次数据只支持前者。

---

## 5. 据此采取的动作

1. **启用降级方案**：图片上传 + 学生手工校正 / 粘贴题面 → 现有 `/messages` 解题链路。阶段 1/2/4/6 的投入不浪费（文件存储、附件 API、配额隔离、前端确认界面均可复用）。
2. **不对外宣称**可靠手写作业识别；界面与文案不出现「自动准确识别」。
3. **不把本次数值写进 `docs/ocr-spike-report.md`**（正式 §26.3 报告尚不存在）。若需引用本报告数值，必须同时标注「GT 为渲染草稿、未经人工复核、样本非真实手写、单 provider、单价未配置」。
4. **issue #2 保持 `open`**：PR #1 已改为 `Refs #2`，合并不会自动关闭；AC-128 实测达标结论待正式 Spike 后单独判定。
